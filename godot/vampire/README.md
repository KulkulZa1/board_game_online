# 뱀파이어 서바이버 — Godot 이식

웹판 뱀서류 게임(`public/arcade/vampire/game.js`)을 웹 플랫폼에서 떼어 내 Godot 4 단독 프로젝트로 옮겼다.
웹판은 그대로 남아 있다 — 이 폴더는 같은 규칙을 Godot 에서 돌리는 **별도 프로젝트**다.
**소스만 커밋한다** — `.godot/`(임포트 캐시)·`export/`(빌드 결과)·`export_presets.cfg`(서명 정보)는 `.gitignore` 로 뺀다.

## 여는 법

1. Godot **4.4 이상 Standard**(.NET 아님)를 설치한다.
2. 프로젝트 매니저 → 가져오기 → 이 폴더의 `project.godot`.
3. ▶ 실행 — 세로 540×960 기준, 창을 가로로 늘리면 월드가 더 넓게 보인다(`aspect=expand`).

| 입력 | 키보드 | 터치 |
|---|---|---|
| 이동 | WASD / 방향키 | 화면 아무 곳이나 눌러 끄는 조이스틱 |
| 대쉬 베기 | Space / X | — (웹판에도 터치 대쉬가 없다) |
| 오버드라이브 | Q | 오른쪽 아래 OD 버튼 |
| 일시정지 | P / Esc | 오른쪽 위 ⏸ |
| 레벨업 선택 · 리롤 | 1 · 2 · 3 · 0 | 카드 / 리롤 버튼 |
| 메인 무기 변경 | 아래쪽 무기 칸 클릭 | 아래쪽 무기 칸 |

시작 화면에서 캐릭터 4종·난이도 4종·맵 3종을 고른다. 웹판의 해금 조건은 메타 진행이라 옮기지 않았으므로 전부 열려 있다.

## 규칙이 웹판과 같은지 확인

```bash
# Godot 없이 (CI 포함) — 표·효과식·XP 곡선을 game.js 와 대조
node prototypes/godot-vampire-port-test.js
```

`vs_rules.gd` 의 표(무기·진화·패시브·시너지·보조 효과·캐릭터·난이도·맵·파워업·아이템)를 JSON 으로 뽑아
`game.js` 의 같은 표와 통째로 비교하고, 패시브·파워업·아이템 효과(`vs_run.gd` 의 `match` 분기)를 **그 GDScript
줄 그대로** JS 로 바꿔 실행해 웹판 `apply` 함수 결과와 맞춘다. `npm run test:games` 에 들어 있다.
이건 GDScript 를 **실행하지는 않는다** — 문법·타입 오류나 실행 중 오류는 아래 Godot 명령으로만 잡힌다.

```bash
# Godot 이 있는 곳에서 — 실제 GDScript 로 판을 돌린다 (저장소 루트에서)
godot --headless --path godot/vampire --script res://tests/sim_test.gd
```

무기 24종을 하나씩 쥐고 20초, 아이템·파워업 전부, 시너지 13종을 켠 채 40초, 레벨업·리롤·진화·메인 무기 변경,
목표 시간→무한 웨이브/승리, 접촉 사망, 캐릭터·난이도별 봇 플레이 2분 30초를 돌린다. 실패하면 종료 코드 1.
Godot 4.4.1 에서 116/116 통과, 약 30초 걸린다. 규칙만 재면 적 650마리에서 틱당 평균 약 2ms 다.
출력에 `SCRIPT ERROR` 가 보이면 그것도 실패다(GDScript 런타임 오류는 그 함수만 멈추고 프로세스는 계속 돈다).

## 구조

| 파일 | 내용 |
|---|---|
| `scripts/vs_rules.gd` | 데이터 표(JSON 호환 문법 — 검사기가 그대로 읽는다)와 순수 함수(`xp_needed` 등) |
| `scripts/vs_run.gd` | 한 판 — `game.js` 의 규칙 함수를 1:1 로 옮겼다 (camelCase → snake_case). 그리기 없음 |
| `scripts/main.gd` + `scenes/main.tscn` | 화면 — `_draw()` 로 월드·HUD 를 그리고, 입력과 패널(UI 는 코드로 만든다) |
| `tests/sim_test.gd` | Godot 헤드리스 검사 (위 명령) |

## 이식하며 지킨 것 — 고치기 전에 읽을 것

- **규칙을 바꾸면 `game.js` 와 `vs_run.gd`/`vs_rules.gd` 를 같이 고친다.** 표가 갈라지면 `test:games` 가 깨진다.
- **적 루프 안에서 피해를 주면 적이 배열에서 빠진다.** 웹판은 역방향 인덱스로 버티지만, 연쇄 폭발이 다른 적을
  같이 죽이면 인덱스가 밀린다. 여기선 복사본을 돌고 `dying` 으로 거른다.
- **콜백 대신 후보 배열.** 웹판 `forEnemiesNear(cb)` 를 `enemies_near()` 로 바꿨다 — GDScript 람다는 지역 변수를
  값으로 잡아서 콜백 안의 `hit = true` 같은 대입이 밖으로 안 나온다.
- **`randf()` 는 1.0 을 낼 수 있다** (`Math.random()` 은 못 낸다). 배열 인덱스는 `_pick(n)` 으로 뽑는다.
- **Dictionary `==` 는 내용 비교다.** 적·투사체는 내부 클래스(참조 비교)로, 타격 기록은 적 `id` 로 한다.
  같은 이유로 `Array.erase(dict)` 는 수백 개짜리 배열에서 프레임마다 O(n²) 이 된다 — 파티클·젬·링·텍스트는
  `_tick_life()` 로 걸러서 새 배열을 만든다.
- **시너지 판정은 캐시한다.** 피해 한 번에 여러 번 불리므로 패시브가 바뀔 때만 다시 계산한다.
- **한글 폰트.** Godot 기본 폰트엔 한글이 없어 `SystemFont` 로 OS 폰트를 쓴다. 배포판에서 모양을 고정하려면
  Pretendard 나 Noto Sans KR(둘 다 OFL)을 번들하고 `main.gd` 의 `_korean_font()` 를 `FontFile` 로 바꾼다.

### 웹판과 일부러 다르게 한 곳 (웹판 버그)

- **진공 청소기 아이템으로 오른 레벨업이 사라진다.** 웹판은 선택지를 고른 뒤 `state = 'playing'` 으로 덮어써서,
  아이템 효과(XP 흡수)가 연 레벨업 창을 닫아 버린다 — 레벨은 오르는데 고를 기회가 없다. 여기선 상태를 먼저 되돌린다.
- **한 번 얼었던 적은 다시 넉백되지 않는다.** 웹판 넉백 조건 `!e.frozen` 은 빙결이 풀리며 `frozen` 이 음수로 남으면
  거짓이 된다. 여기선 '빙결 중일 때만' 넉백을 막는다.
